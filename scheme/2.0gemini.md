# 项目规格说明书：基于 OpenStack 日志的大数据 AIOps 智能诊断系统

## 1. 项目概述 (Executive Summary)

本项目构建一个端到端的 AIOps（智能运维）系统，模拟真实的云平台运维场景。系统通过**流式计算**实时监控 OpenStack 组件日志，利用**机器学习（随机森林）** 毫秒级识别故障，一旦检测到异常，自动触发**大语言模型（LLM）** 进行根因分析并生成修复建议，最终通过可视化大屏展示。

* **核心理念**：Lambda 架构（离线训练 + 在线实时处理）。
* **技术亮点**：**“快慢模型协同”** —— 小模型（Random Forest）负责实时、低成本的异常过滤；大模型（LLM）负责高价值、深度的故障诊断。

## 2. 技术栈与数据集 (Tech Stack & Data)

### 2.1 数据集 (Dataset)

采用 [ParisaKalaki/openstack-logs](https://github.com/ParisaKalaki/openstack-logs) 数据集。

* **训练数据**：`normal_1.csv`, `normal_2.csv` (标记为 Normal), `abnormal_1.csv` (标记为 Fault)。
* **测试/回放数据**：保留一部分 `abnormal_2.csv` 或原始 `.log` 文件用于实时回放演示。

### 2.2 技术选型

* **数据源模拟**：Python Script (Log Replayer)
* **消息队列**：**Kafka** (缓冲削峰)
* **流计算引擎**：**Spark Streaming** (PySpark)
* **机器学习**：**Scikit-learn** (TF-IDF + RandomForest)
* **后端服务**：**FastAPI** + Pydantic
* **大模型**：OpenAI API / DeepSeek API (或者本地 Ollama)
* **存储层**：
* **HBase**: 存储原始日志详情（模拟海量日志存储）。
* **MariaDB/SQLite**: 存储告警事件、统计元数据。


* **前端**：**Vue 3** + Astro + TailwindCSS + ECharts/vue-data-ui
* **部署**：Docker Compose

## 3. 系统架构设计 (Architecture)

### 3.1 模块划分

系统分为四个核心管道（Pipeline）：

1. **离线训练管道 (Offline Pipeline)**：处理 CSV -> 训练分类模型 -> 生成 `.pkl` 文件。
2. **在线模拟管道 (Simulation Pipeline)**：读取日志文件 -> 模拟时间间隔 -> 推送 Kafka。
3. **实时计算管道 (Streaming Pipeline)**：消费 Kafka -> 预处理 -> 模型推理 -> 存库。
4. **诊断与交互管道 (Service Pipeline)**：前端轮询 -> 后端查询 -> 调用 LLM -> 展示报告。

## 4. 详细实施步骤 (Implementation Specs)

### 第一阶段：离线模型训练 (The Brain - Offline)

**目标**：训练一个能区分“正常日志”和“不同错误类型”的轻量级模型。

1. **数据清洗**：
* 读取 CSV，提取 `Log_Content` 列。
* **正则模版化 (Templating)**：将具体数字、IP、UUID 替换为通配符。
* *例*：`instance: 5b4c...`  `instance: <ID>`




2. **特征工程**：
* 使用 `TfidfVectorizer` 将文本转为向量。


3. **模型训练**：
* 算法：`RandomForestClassifier` (随机森林)。
* 标签映射：`Normal` -> 0, `Nova-Compute-Error` -> 1, `Neutron-Error` -> 2 等。


4. **产出物**：
* `log_classifier.pkl` (模型)
* `vectorizer.pkl` (向量化器)
* `template_patterns.json` (正则清洗规则)



### 第二阶段：日志回放器 (Log Replayer)

**目标**：让静态文件“动”起来，模拟生产环境流量。

1. **功能**：
* 读取测试集的 CSV 或 log 文件。
* **模拟延迟**：在发送每条日志之间随机 `time.sleep(0.01 ~ 0.5)`。
* **注入故障**：允许按键触发，瞬间发送 50 条异常日志（模拟故障爆发）。


2. **输出**：写入 Kafka Topic `openstack_logs`。
* *Payload*: `{"timestamp": "...", "service": "nova", "content": "Raw log content..."}`



### 第三阶段：流式处理 (Spark Streaming)

**目标**：实时消费，实时判断。

1. **初始化**：启动时加载 `.pkl` 模型文件。
2. **处理逻辑** (Micro-batch 5秒):
* 从 Kafka 拉取数据。
* 对 `content` 应用同样的**正则模版化**。
* 调用 `model.predict()`。


3. **分支处理**：
* **Case A (Normal)**:
* 统计计数器 +1。
* 存入 HBase `log_archive` 表 (RowKey: Timestamp_UUID)。


* **Case B (Abnormal)**:
* 构造告警对象：`{time, raw_content, predicted_error_type}`。
* 写入 MariaDB `alerts` 表 (状态设为 `pending`)。
* 写入 HBase。





### 第四阶段：后端 API 与 LLM 诊断 (The Doctor)

**目标**：连接数据与前端，提供智能解释。

1. **接口设计**：
* `GET /api/stats`: 返回今日日志总量、异常总量（读 Redis 或 DB 统计）。
* `GET /api/alerts`: 返回告警列表（从 MariaDB）。
* `POST /api/diagnose/{alert_id}`: 触发 LLM 分析。


2. **LLM 逻辑**：
* 后端收到请求，根据 `alert_id` 查出日志内容。
* **Prompt 模版**：
> "系统检测到 OpenStack Nova 组件异常。
> 日志内容：'{log_content}'
> 预测类型：{error_type}
> 请给出：1. 故障根因简述；2. 建议的 Linux 修复命令。"


* 调用 LLM API，将返回结果更新到数据库 `llm_analysis` 字段。



### 第五阶段：前端可视化 (The Face)

**目标**：展示结果，震撼演示。

1. **布局**：
* **顶部**：KPI 卡片（System Health Score, Log Throughput）。
* **中部**：实时折线图（ECharts），X轴为时间，Y轴为每秒日志数。绿线代表 Normal，红线代表 Abnormal。
* **底部**：滚动告警列表。


2. **交互**：
* 列表中的“异常项”高亮显示。
* 点击“智能分析”按钮，弹出对话框，打字机效果展示 LLM 的分析结果。

## 5. 数据库设计 (Schema)

### 5.1 MariaDB (关系型数据)

**Table: `alerts**`
| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | INT (PK) | 自增 ID |
| `timestamp` | DATETIME | 异常发生时间 |
| `service` | VARCHAR | 组件名 (nova, neutron) |
| `log_content` | TEXT | 原始日志片段 |
| `error_type` | VARCHAR | 模型预测的故障类型 |
| `llm_analysis`| TEXT | **LLM 生成的诊断报告** |
| `status` | VARCHAR | pending / analyzed / resolved |

### 5.2 HBase (大数据存储)

**Table: `all_logs**`

* **RowKey**: `<Reverse_Timestamp>_<Service_Name>` (设计为按时间倒序快速查询)
* **Column Family**: `info`
* `content`: 原始日志
* `is_abnormal`: '0' or '1'
